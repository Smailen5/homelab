# Caso 0001: warning `smartd` sulla lettura del self-test log NVMe

- Data: 2026-09-29
- Macchina: `monday`
- Dominio: LPI 101 storage · troubleshooting hardware
- Issue di riferimento: [#73 — bug: controllo disco possibili problemi](https://github.com/Smailen5/homelab-config/issues/73)

> Nota: la issue vive nella repo **privata** `homelab-config`, quindi il link non e' raggiungibile dalla repo pubblica. E' comunque tenuto qui perche' serve a collegare questo caso alla sua cronologia di lavoro.

## Sintomo

Il **2026-09-27 14:01** il servizio `smartd` del nodo Proxmox `monday` ha inviato una mail di allarme. Il messaggio segnala un errore sulla lettura del log dei self-test del disco di sistema `/dev/nvme0` (SSD NVMe 512 GB, quello che ospita il sistema e i dischi delle VM).

Testo integrale della mail:

```txt
This message was generated by the smartd daemon running on:

   host name:  monday
   DNS domain: smailenvargas.com

The following warning/error was logged by the smartd daemon:

Device: /dev/nvme0, Read Self-test Log failed: Host Pathing Error (0x370)


Device info:
AirDisk 512GB SSD, S/N:QH6457W…1129, FW:SN27911, 512 GB

For details see host's SYSLOG.

You can also use the smartctl utility for further investigation.
Another message will be sent in 24 hours if the problem persists.
```

Elementi che hanno generato la preoccupazione:

- il dispositivo indicato e' il **disco di sistema**, quindi un suo guasto metterebbe fuori uso il nodo e tutte le VM/CT.
- `smartd` avvisa che **ripetera' la mail ogni 24 ore** finche' il problema persiste.
- la formulazione e' ambigua: parla di lettura di un log fallita, non di un guasto esplicito, ma senza verifica non era distinguibile un errore di compatibilita' da un disco in sofferenza.

## Diagnosi

Analisi condotta il **2026-09-29 dalle 13:53 alle 13:55 (CEST)** con accesso SSH al nodo.

### Metodo

L'interpretazione della mail e dei log e' stata fatta con il supporto di un **assistente AI**, che ha:

- spiegato il significato di `Read Self-test Log failed: Host Pathing Error (0x370)`: si tratta della lettura della *log page 0x06* (self-test log) del controller NVMe, non di un errore sui dati;
- suggerito di **verificare con `smartctl`** i dati di salute reali del disco e di provare la lettura del self-test log;
- consigliato di installare **`nvme-cli`** per interrogare direttamente il controller NVMe con i comandi nativi `nvme`.

### Comandi eseguiti

```bash
# Suite smartmontools (gia' presente, versione 7.5)
sudo smartctl -a /dev/nvme0          # salute, usura, temperature, error log, self-test log
sudo smartctl -x /dev/nvme0          # le stesse informazioni in forma estesa
sudo smartctl -l selftest /dev/nvme0 # lettura esplicita del self-test log (log page 0x06)

# Ricerca e installazione dello strumento NVMe nativo
apt search nvme
sudo apt install nvme-cli

# Interrogazione diretta del controller NVMe
sudo nvme smart-log /dev/nvme0       # log 0x02 (SMART/Health)
sudo nvme error-log /dev/nvme0       # log 0x01 (error information)
sudo nvme self-test-log /dev/nvme0   # log 0x06 (self-test)
```

### Software installato per la diagnosi

| Pacchetto | Versione | Perche' |
| --- | --- | --- |
| `nvme-cli` | 2.13-2 | Interrogare il controller NVMe con i comandi nativi `nvme`, come strumento indipendente rispetto a `smartmontools` |

Installazione suggerita dall'assistente AI per avere una seconda fonte di lettura del dispositivo. **Nessun'altra modifica e' stata applicata al sistema.**

### Risultati

Tutte le fonti concordano su un disco sano:

| Indicatore | Valore | Esito |
| --- | --- | --- |
| SMART overall-health | PASSED | ok |
| Critical Warning | `0x00` | nessun allarme |
| Available Spare | 100% (soglia 10%) | ok |
| Percentage Used | 4% | usura minima |
| Media and Data Integrity Errors | 0 | nessun errore sui dati |
| Error Information Log Entries | 0 (`No Errors Logged`) | error log vuoto |
| Temperatura | 43–47 °C (soglie 90/95 °C) | ok |
| Power On Hours | 6761 | uso normale |
| Unsafe Shutdowns | 20 | storico, non correlato all'evento |

Lettura del self-test log (log page 0x06), sia con `smartctl -l selftest` sia con `nvme self-test-log`:

```txt
Self-test status: No self-test in progress
No Self-tests Logged
```

`nvme smart-log` restituisce gli stessi valori di `smartctl -a` (legge la medesima log page 0x02): conferma incrociata, nessuna anomalia. Anche `nvme error-log` e `nvme self-test-log` non riportano nulla.

**Conclusione della diagnosi:** l'errore segnalato da `smartd` **non e' riproducibile** a comando e il disco risulta sano su tutte le metriche. Si potrebbe trattare quindi di un **falso positivo intermittente**, plausibilmente legato alla lettura del self-test log da parte di `smartd` su questo controller/firmware NVMe, e non di un guasto hardware.

## Rimedio

**Nessun rimedio applicato**, per scelta consapevole.

- Il disco e' sano e i servizi funzionano: non c'e' un'urgenza e non si e' voluto modificare la configurazione (`smartd.conf`, kernel, firmware del disco) senza prima aver capito la causa esatta.
- Il warning e' stato quindi **accettato come noto e tollerato per il momento**: si continua a ricevere la mail di reminder ogni 24 ore finche' il problema persiste.
- Lo studio per eliminare definitivamente il warning (capire quando e perche' la lettura del self-test log fallisce, ed eventualmente silenziare quel controllo specifico o aggiornare/aggirare lo strumento) e' rinviato a un momento successivo, con la calma di documentarsi prima di toccare la configurazione della macchina.

Nessuna modifica e' stata fatta ai file della macchina ne' alla sua configurazione.

## Verifica

- `smartctl -a` e `smartctl -x` → `SMART overall-health self-assessment test result: PASSED`, `Critical Warning: 0x00`, `Media and Data Integrity Errors: 0`, `Error Information Log Entries: 0`.
- `smartctl -l selftest` → il log 0x06 **si legge correttamente** e risulta vuoto: l'errore della mail non si e' piu' manifestato durante la verifica.
- `nvme smart-log`, `nvme error-log`, `nvme self-test-log` → nessuna anomalia, valori coerenti con `smartctl`.
- Il nodo `monday` e le VM/CT ospitate risultano regolarmente in funzione durante tutte le verifiche.
- A distanza di circa 48 ore dalla segnalazione del 27/09 non sono arrivate altre mail di `smartd`. Poiche' la notifica e' prevista ogni 24 ore *solo se il problema persiste*, la sua assenza indica che l'errore non si e' piu' ripresentato.
